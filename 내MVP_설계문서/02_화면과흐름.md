# 02 · 화면과 흐름

상태: 구현 전 화면 제안. 화면 캡처가 없어 실제 버튼은 확인하지 못했습니다. 아래 버튼은 모두 ‘예정’이며 현재 존재한다고 주장하지 않습니다. 수업의 실제 버튼 일치 기준은 구현 후 재검사합니다.

## 고객 화면 — guide.html (예정)

위에서부터 소개 문구, 노선번호 검색칸, 이 기기의 관심 노선, 검색 결과 카드, 노선 상세와 변경 안내, 제보 창을 배치합니다. 하나의 고객 화면 안에서 상세·폼을 펼칩니다.

카드에는 노선번호, 방향 이름, 공식 출처, 마지막 확인 시각을 표시합니다. 상세에는 공개·검증된 안내만 보입니다. ‘정보 없음’은 ‘정상 운행’과 다릅니다. 정류소 도착 시각은 MVP에서 계산하지 않습니다.

## 관리자 화면 — admin.html (예정)

공식 자료 확인 후 노선 저장, 변경 안내 작성, 제보 검토, 공개·숨김을 수행합니다. AI 초안 칸은 후속 기능으로만 설계합니다. 관리자 인증 방식을 검증하기 전에는 외부 공개하지 않습니다.

## 버튼 흐름 표 — 전부 제안

| 화면 | 버튼 | 일어나는 일 | 서버 함수 / 저장 |
| --- | --- | --- | --- |
| 고객 | 검색 | 노선번호로 공개된 방향별 카드 표시 | searchRoutes |
| 고객 | 상세 보기 | 선택한 route_id의 유효 안내 조회 | getRouteDetail |
| 고객 | 관심 저장 / 해제 | 선택 노선을 이 브라우저에 저장·삭제 | 서버 없음, localStorage |
| 고객 | 새로고침 | 현재 검색·상세 재조회. 실패하면 기존 확인 시각 유지 | searchRoutes 또는 getRouteDetail |
| 고객 | 공식 정보 확인 | 검토된 공식 원문 URL 열기 | 서버 없음, 안전한 외부 링크 |
| 고객 | 제보하기 | 노선이 선택된 제보 창 열기 | 서버 없음 |
| 고객 | 제보 보내기 | 유형·내용 검증 후 비공개 접수번호 표시 | submitReport / REPORTS |
| 고객 | 취소 / 닫기 | 제보 창 또는 상세 닫기 | 서버 없음 |
| 관리자 | 관리 자료 불러오기 | 권한 검사 후 관리 목록 표시 | getAdminData |
| 관리자 | 노선 저장 | 검증된 노선·방향·공식 링크 저장 | saveRoute / ROUTES |
| 관리자 | 안내 저장 | 출처·시행 기간·안내 내용을 초안으로 저장 | saveNotice / NOTICES |
| 관리자 | 제보 검토 저장 | 검토 메모·검증 결과 갱신 | reviewReport / REPORTS |
| 관리자 | 공개 / 숨김 | 대상과 검증 조건 확인 후 상태 변경 | setPublication / 해당 탭 |

AI 버튼은 MVP에 추가하지 않습니다. 05의 설계가 승인되고 비용 범위가 확인되면 별도로 추가합니다. 지도앱 자동 비교·스크래핑 버튼도 없습니다.

## 사용자 이야기 — 5줄

1. 고객이 로그인 없이 고객용 주소를 열고 탈 버스의 노선번호를 검색합니다.
2. 검색 결과에서 목적지 방향을 구분해 상세를 엽니다.
3. 변경 안내의 적용 기간·출처·확인 시각을 읽고 공식 원문을 확인합니다.
4. 자주 타는 노선은 관심 노선으로 저장하고, 안내와 다른 점이 있으면 제보합니다.
5. 접수번호를 확인하고 종료합니다. 다음 접속 때 관심 노선의 안내를 다시 확인합니다.

## 예외 처리

- 같은 번호에 여러 방향이 있으면 자동 선택하지 않고 각각 표시합니다.
- 관심 노선 저장 실패 시 저장됐다고 표시하지 않습니다. 저장소 삭제 시 관심 노선도 사라집니다.
- 유효 기간이 끝난 안내·숨김·미검증 제보는 고객에게 보내지 않습니다.
- 공식 링크가 열리지 않으면 최종 확인 시각과 재확인 필요를 표시하며 도착 시각을 추정하지 않습니다.
- 접수번호는 저장 성공 후에만 표시. 중복 클릭은 서버에서도 request_id로 중복 방지합니다.

## 확인 필요

실제 버튼·레이아웃·고객 URL·관리자 인증·현장 사용성 모두 미검증입니다. 현재 노선번호 검색만 제안했으며 출도착 경로 탐색과 정류소 검색은 후속 범위입니다.
