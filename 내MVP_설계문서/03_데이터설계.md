# 03 · 데이터 설계

상태: 신규 설계안. 실제 시트 1행과 코드 HEADERS가 제공되지 않았습니다. **아래 모든 입력 규칙은 제안이며 코드에 구현됐다는 뜻이 아닙니다. 코드상 규칙은 미확인입니다.** 기존 시트가 있다면 시트를 바꾸지 말고 이 문서를 실제 순서에 맞춥니다.

각 탭의 아래 표 순서가 제안 HEADERS 순서입니다. 예시는 전부 가상이며 실제 노선·시간·공지가 아닙니다. 실제 고객 개인정보·키·관리자 주소는 저장하지 않습니다.

## ROUTES — 한 줄 = 노선의 한 방향 또는 분기

같은 노선번호라도 방향·분기가 다르면 route_id를 따로 부여합니다. route_no를 고유 키로 사용하지 않습니다.

| 순서·필드 | 뜻 | 가상 예시 | 제안 규칙 | 노출 / 이유 |
| --- | --- | --- | --- | --- |
| 1 route_id | 내부 식별자 | R-DEMO-A | 필수·유일·수정 불가 | 고객 가능 / 행 구분 |
| 2 route_no | 노선번호 문자열 | 예시-01 | 필수·1~20자 | 고객 / 검색 |
| 3 direction_name | 방향·분기 설명 | 예시 종점 방면 | 필수·1~80자 | 고객 / 반대 방향 구별 |
| 4 source_url | 공식 원문 | 공식 원문 링크 | 필수·HTTPS·허용 도메인 검사 | 고객 / 근거 확인 |
| 5 checked_at | 사람이 원문 확인한 시각 | 테스트 기준시각 | 필수·서버 시간·KST 표시 | 고객 / 최신성 판단 |
| 6 status | 공개 상태 | draft | draft/published/hidden | 관리자 / 게시 제어 |

고객 조회는 published 행만 반환합니다. 공식 도메인 허용 목록의 초안은 bus.jeju.go.kr이며 실제 원문 링크 확인 후 관리 설정으로 확정합니다.

## NOTICES — 한 줄 = 한 노선 방향에 대한 안내

여러 방향에 적용되는 공지는 방향별로 따로 연결합니다. 같은 source_url 사용은 허용합니다.

| 순서·필드 | 뜻 | 가상 예시 | 제안 규칙 | 노출 / 이유 |
| --- | --- | --- | --- | --- |
| 1 notice_id | 안내 ID | N-DEMO | 필수·유일 | 고객 / 행 구분 |
| 2 route_id | 대상 노선 방향 | R-DEMO-A | ROUTES에 존재 | 고객 / 노선 연결 |
| 3 kind | 안내 종류 | route_change | route_change/timetable_change/detour/cancellation/other | 고객 / 구분 |
| 4 title | 제목 | 테스트용 변경 안내 | 필수·1~80자 | 고객 / 핵심 |
| 5 body | 안내 본문 | 테스트 내용 | 필수·1~600자·HTML 실행 금지 | 고객 / 설명 |
| 6 valid_from | 적용 시작 | 테스트 시작일 | 필수·YYYY-MM-DD | 고객 / 시행일 |
| 7 valid_to | 적용 종료 포함일 | 테스트 종료일 | 선택·시작 이상·빈 값은 별도 확인 대상 | 고객 / 기간 |
| 8 source_url | 공식 근거 | 공식 원문 링크 | 공개 시 필수·허용 도메인 HTTPS | 고객 / 원문 확인 |
| 9 source_published_at | 원문 게시일 | 테스트 게시일 | 선택·모르면 비움·시행일과 구분 | 고객 / 날짜 혼동 방지 |
| 10 checked_at | 관리자 확인 시각 | 테스트 기준시각 | 공개 시 필수·서버 시간 | 고객 / 최신성 |
| 11 verification | 확인 상태 | unverified | unverified/verified/conflict | 고객 / 근거 상태 |
| 12 status | 공개 상태 | draft | draft/published/hidden | 관리자 / 제어 |

공개 조건: verification=verified, 필수 필드 충족, 연결 노선 공개. 고객에는 적용 시작 이후·종료일까지 안내합니다(KST 날짜 기준). 종료 미상 안내는 확인 시각에서 7일 후 ‘재확인 필요’로 분리하고 최신 변경 안내에서 제외하는 정책을 제안합니다. 7일은 검증된 교통 기준이 아닌 운영 초안입니다.

## REPORTS — 한 줄 = 이용자 제보

| 순서·필드 | 뜻 | 가상 예시 | 제안 규칙 | 노출 / 이유 |
| --- | --- | --- | --- | --- |
| 1 report_id | 접수번호 | P-DEMO | 서버 생성·유일 | 제출자에게만 / 접수 확인 |
| 2 request_id | 중복 방지 키 | UUID 예시 | 필수·유일·재전송 시 동일 | 관리자 / 중복 방지 |
| 3 route_id | 대상 방향 | R-DEMO-A | 공개 ROUTES 존재 | 고객 가능 / 연결 |
| 4 category | 유형 | timetable | timetable/direction/notice_mismatch/other | 고객 가능 / 분류 |
| 5 content | 원문 | 안내가 서로 달라요 | 필수·10~500자·개인정보 입력 금지 안내 | 관리자 / 개인정보·미확인 주장 |
| 6 created_at | 접수 시각 | 테스트 기준시각 | 서버 생성 | 관리자 / 접수 관리 |
| 7 verification | 검증 결과 | unverified | unverified/verified/conflict | 관리자 / 판단 |
| 8 review_note | 내부 검토 메모 | 공식 원문 확인 대기 | 선택·500자 이내 | 관리자 / 내부 기록 |
| 9 public_summary | 공개용 정리 | 공식 정보 재확인 안내 | 공개 시 1~300자·원문 복사 금지 | 고객 / 검토된 내용만 |
| 10 source_url | 검증 공식 근거 | 공식 원문 링크 | 공개 시 필수·허용 도메인 HTTPS | 고객 / 근거 |
| 11 checked_at | 검토 확인 시각 | 테스트 기준시각 | 공개 시 필수·서버 시간 | 고객 / 최신성 |
| 12 valid_until | 제보 공개 기한 | 테스트 종료일 | 공개 시 필수·오늘 이상 | 고객 / 오래된 경험 제거 |
| 13 status | 처리·공개 상태 | received | received/reviewing/published/hidden/rejected | 관리자 / 검토 흐름 |

흐름: received → reviewing → published 또는 rejected. published는 hidden으로 전환 가능. 재공개 전 재검증. 제보 원문은 고객에게 반환하지 않으며 공개용 응답에는 3·4·9·10·11·12 필드만 허용합니다. 노선 숨김·공개기한 경과·verification 불일치 시 공개 제보도 제외합니다.

## MESSAGES — 후속 AI 기능용, MVP에서는 만들지 않아도 됨

| 순서·필드 | 뜻 | 가상 예시 | 제안 규칙 | 노출 / 이유 |
| --- | --- | --- | --- | --- |
| 1 message_id | 초안 ID | M-DEMO | 서버 생성·유일 | 관리자 / 식별 |
| 2 notice_id | 근거 안내 | N-DEMO | 검증된 NOTICES 존재 | 관리자 / 추적 |
| 3 ai_text | AI 원문 | 테스트 초안 | 최대 300자·수정하지 않고 보존 | 관리자 / 원문 기록 |
| 4 final_text | 사람이 고친 글 | 테스트 최종문 | 게시 시 1~300자 | 관리자 / 편집본 |
| 5 status | 상태 | draft | draft/reviewed/archived | 관리자 / 검토 |
| 6 created_at | 생성 시각 | 테스트 기준시각 | 서버 생성 | 관리자 / 이력 |
| 7 reviewed_at | 확인 시각 | 테스트 기준시각 | reviewed 때 필수 | 관리자 / 확인 |

MESSAGES 자체를 공개하지 않습니다. 확인된 final_text를 NOTICES.body에 반영한 후 별도 공개 절차를 거칩니다. NOTICES의 날짜·근거 필드는 AI가 수정하지 않습니다.

## 저장소 공통 제안

- 날짜·시간은 서버 기준으로 저장하고 화면에는 Asia/Seoul로 표시합니다. 적용일은 날짜 값, checked_at은 시각 값입니다.
- 시트 수식으로 해석될 수 있는 =, +, -, @ 시작의 사용자 입력은 텍스트로 저장합니다. 출력도 HTML 이스케이프합니다.
- 상태 변경·중복 접수 처리에는 잠금과 유일성 검사가 필요합니다.
- 개인정보를 요구하지 않습니다. 실수로 포함된 제보는 비공개 유지·삭제하고, 비공개 제보 원문은 90일 후 삭제하는 운영안을 제안합니다. 기간은 운영자 확정 필요.
- 관심 노선은 브라우저에 route_id 배열로 저장합니다. 별도 회원·알림 구독 탭은 없습니다.

## 확인 필요

실제 HEADERS·입력 규칙·공식 데이터 ID·시트 ID·관리자 권한 구현은 미확인입니다. 규칙이 없는 기존 코드가 발견되면 ‘규칙 없음’으로 기록하고 위 제안과 분리해야 합니다.
