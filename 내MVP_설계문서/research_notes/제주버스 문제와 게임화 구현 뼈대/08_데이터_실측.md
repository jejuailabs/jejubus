## 시간표·첫차·막차·배차를 공식적으로 얻는 방법, 사이트 구조와 약관

### Takeaway
TAGO와 제주 노선 기본정보 API에는 시간표가 없다. 공식 원천은 BIS 공개 시간표 페이지(`/schedule/viewNew/{노선번호}`)와 공지 첨부 엑셀이다. 페이지는 회차별 표, 첫차·막차·배차 문구, 시행일을 보여 주지만 표는 자바스크립트로 그려지고 형식이 노선마다 다르다. 이용약관은 찾지 못했으므로, 대량 수집과 재배포 전에 제주도에 문의해야 한다.

### Cited Findings
- TAGO `getRouteInfoIem`을 8개 ID에 조회한 결과 `intervaltime`은 전부 0이고, 첫차·막차 필드는 응답에 없었다(201, 202, 303, 3004, 888, 102, 181) — [실측 getRouteInfoIem](https://apis.data.go.kr/1613000/BusRouteInfoInqireService/getRouteInfoIem)
- 제주특별자치도 노선 기본 정보 API 필드는 노선ID, 노선이름, 노선번호, 시작·종착 정류소, 정류소개수, 노선거리뿐이다. 수정일은 포털 페이지 기준 2026-10-15이고 시간표 필드는 없다 — [data.go.kr 15074254](https://www.data.go.kr/data/15074254/openapi.do). 검색 도구 요약의 수정일 2021-02-05는 페이지 직접 확인값과 다르므로 쓰지 않는다
- 공개 시간표 URL: `https://bus.jeju.go.kr/schedule/viewNew/201` 형태다. 정적 HTML의 표는 비어 있고, 페이지가 렌더링 시 POST로 표를 채운다. 내장 코드에는 `/data/schedule/getScheduleInfo`, `getScheduleTableInfo`가 있다 — [BIS 201 시간표](https://bus.jeju.go.kr/schedule/viewNew/201), [BIS 181](https://bus.jeju.go.kr/schedule/view/181)
- 렌더링 결과 201번 1탭은 63회차이고, 헤더는 "첫차(성산일출봉 출발) 5:43, 막차 21:35, 배차간격 15~22분, 금남여객", 시행일은 2024.8.1이다. 행은 경유지별 시각과 ○/X 경유 표시, 종료 지점 주석을 담는다 — [BIS 201 시간표](https://bus.jeju.go.kr/schedule/viewNew/201)
- 무작위 표본 16개 노선번호(시드 고정): 첫차 문구 11개, 시행일 표기 16개 모두. 평일·휴일 또는 토요일 탭이 따로 있는 노선 3개(365, 722-1, 741-1), 호출형 2개(722-1, 741-1), 운행 중단 1개(1113)다 — [BIS 365](https://bus.jeju.go.kr/schedule/viewNew/365), [BIS 722-1](https://bus.jeju.go.kr/schedule/viewNew/722-1), [BIS 741-1](https://bus.jeju.go.kr/schedule/viewNew/741-1), [BIS 1113](https://bus.jeju.go.kr/schedule/viewNew/1113)
- 표에는 자유 문구 조건이 섞여 있다. 예: "막차 3회 승객없으면 함덕 5구까지 운행", "종점 방면 승객 없는 경우 신례교 종료", 방학기간 영주고 운행 문구, "토,공휴일 운행 안함" — [BIS 312](https://bus.jeju.go.kr/schedule/viewNew/312), [BIS 621](https://bus.jeju.go.kr/schedule/viewNew/621), [BIS 365](https://bus.jeju.go.kr/schedule/viewNew/365), [BIS 312-1](https://bus.jeju.go.kr/schedule/viewNew/312-1)

- 결행 페이지는 서버 렌더링 표로 내용이 읽힌다. 열은 결행 일시, 결행 사유, 노선명, 회차, 차량번호, 운수사다. 2026-11-06 23:2x 조회 결과는 "조회된 결과가 없습니다."였다. 검색 폼은 POST에 `csrf_token`이 있다 — [BIS 버스 결행 안내](https://bus.jeju.go.kr/busCancellationInfo/cancellationList)
- `robots.txt`는 404이고, 조회한 페이지에서 "이용약관" 문구나 공공누리 표시를 찾지 못했다. 바닥글에는 개인정보처리방침과 "COPYRIGHT JEJU BUS INFORMATION SYSTEM ALL RIGHTS RESERVED."가 있고, 문의처는 064-710-2447이다 — [robots.txt](https://bus.jeju.go.kr/robots.txt), [BIS 메인](https://bus.jeju.go.kr/)
- 공개 스크립트에서 내부 JSON 경로가 보인다. `/data/search/getLineInfoByLineId`, `getLinkInfoByLineId`, `getRealTimeBusPositionByLineId`, `getArriveScheduleByStationId`, `getStationInfoByStationId`, `searchSimpleLineListByLineNum` 등이다. 약관 근거가 없고 공개 웹페이지만 읽으라는 범위 밖이어서 **직접 호출하지 않았다**. 다만 시간표 페이지 렌더링 시 페이지 자체가 `/data/schedule/*`를 호출했다 — [searchContol.js](https://bus.jeju.go.kr/resources/layouts/web/searchContol.js)
- data.go.kr 검색 1회에서는 제주 시간표 전용 공공 API를 찾지 못했다. 없다는 증명은 아니다 — [data.go.kr 15074254](https://www.data.go.kr/data/15074254/openapi.do)

### Inferences
- 시간표 기반 기능(막차 경고, 놓치면 대기시간)은 가능하다. 데이터는 공식 페이지에 있고 노선번호로 찾을 수 있다. 다만 파서가 아니라 **검수 절차가 포함된 반자동 수집**으로 잡아야 한다. 표 열 구조, 주석, 평일·휴일 분리가 노선마다 달라서다.
- 첫차·막차 문구는 11/16에 있지만, "첫차(…출발)"처럼 기준 정류장이 다르다. 사용자 정류장 기준 시각은 표의 칸을 읽거나 추정해야 한다. 추정이면 UI에 [추정]으로 표시한다.
- 평일·주말을 탭으로 나누지 않은 다수 노선은 주말 운행 차이가 없다고 단정하면 안 된다. 표본 범위 안의 관찰일 뿐이다.
- 페이지 시행일은 신선도 신호로 쓸 수 있지만 절대 기준은 아니다. 16/19가 맞아 유용하나 102, 202처럼 공지 없이 믿으면 틀린다.
- `getLinkInfoByLineId`는 이름상 도로 선형일 수 있어 노선선 문제를 크게 줄일 가능성이 있다. 내용은 확인하지 않았다. 사용 전 제주도 담당(064-710-2447)에 허용 여부와 재배포 조건을 묻는 것이 먼저다.
- 이용약관이 없다는 것은 허용을 뜻하지 않는다. 바닥글이 권리 유보를 표시하므로, 노선별 시간표를 앱 DB로 재배포하기 전에 문의 기록을 남겨야 한다.

### Gaps
- 엑셀은 파일 내려받기에 해당하고 지시 범위가 읽기 전용이라 내려받지 않았다. 엑셀 구조, 표 내용과의 일치 여부는 미확인이다.
- 102·202의 표 내용이 7월 변경분을 반영했는지는 확인하지 못했다. 공지 첨부와 대조해야 한다.
- 헤드리스 렌더링은 첫 탭 기준이라, 반대 방향과 휴일 탭의 표는 확인하지 않았다. 다중 탭 페이지의 시행일도 첫 탭 표기다.
- 결행 페이지는 1회 조회로 0건이었다. 평소 쓰이는지 알 수 없고, 호우·태풍일에 재조회가 필요하다.
- 공식 시간표의 저작물 이용 조건과 공공데이터 개방 여부는 문의 전까지 불명이다.
- 시간표 대비 실제 운행(정시성)은 측정하지 못했다.

## TAGO 정류장 좌표로 실제 도로 노선선을 만들 수 있는가

### Takeaway
도심 노선 1개(3004번)에서는 가능했다. 정류장을 도로에 14 m 안에 붙였고, 실제 차량 위치와의 거리 중앙값은 7.5 m였다. 그러나 이는 자동차 프로필의 도심 단일 노선 시험이다. 공개 서버는 노선 전수 생성에 쓰면 안 되므로, 전체 생성은 06 문서대로 오프라인 도구로 해야 한다.

### Cited Findings
- 정책: 현재 데모로 안내되는 routing.openstreetmap.de는 초당 1회 상한, "No scraping, no heavy usage", 유효한 User-Agent, 표기와 지도 수정 링크를 요구한다. 상세 정책은 독일어 FOSSGIS 페이지에 있다 — [FOSSGIS Routing 안내](https://routing.openstreetmap.de/about.html)
- OSRM 위키 정책은 과도한 사용 금지, 위조 User-Agent 금지, 접근 판매 금지, ODbL 표기를 적고 있고, 이전 데모 서버 기준이라고 밝힌다. 위키 마지막 수정은 2020-12-17이다 — [OSRM Api usage policy](https://github.com/Project-OSRM/osrm-backend/wiki/Api-usage-policy)
- 시험: 위 정책 안에서 3004번 1개 ID(`JEB405900401`, 정류장 33개)로 `routed-car` 경로 요청 2회(기본, `approaches=curb`)를 보냈다. 두 결과 모두 15.91 km, 24.9분, 좌표 451개로 같았다 — [실측 routing.openstreetmap.de](https://routing.openstreetmap.de/about.html)
- 정류장 스냅 거리는 중앙값 7.5 m, 최대 14.2 m다. 직선거리 합 13.32 km 대비 비율은 1.19이고, 32개 구간 중 2배 초과 우회 구간(300 m 이상)은 0개다 — [실측](https://routing.openstreetmap.de/about.html)
- 실제 위치 대조: 같은 ID의 측정 좌표 52건(14~25번째 구간)과 경로선의 거리는 중앙값 7.5 m, 90분위 37.5 m, 95분위 47.3 m, 최대 70 m다. 30 m 초과가 11건이다 — [실측](https://routing.openstreetmap.de/about.html), [실측 위치](https://apis.data.go.kr/1613000/BusLcInfoInqireService/getRouteAcctoBusLcList)

### Inferences
- 3004는 시내 구간 노선이라 가장 쉬운 사례에 가깝다. 201번처럼 187정류장에 경유 분기가 있고, 해안도로·마을 안길·회차가 많은 노선에서 같은 품질을 기대할 근거는 없다.
- `approaches=curb`가 결과를 바꾸지 않았다. 시험 노선에서 효과가 없었거나 옵션이 적용되지 않은 것인데, 어느 쪽인지 모른다. 정류장 측면 처리에 기대면 안 된다.
- 994개 ID를 공개 서버에 넣는 것은 정책 위반 소지가 있다. 고유 정류장 순서 기준으로 줄이더라도 자체 OSRM이나 pfaedle로 돌린다. 이건 06 문서의 결론과 같다.
- 공개 서버 산출물은 ODbL 표기가 따라온다. 공개 전에 표기 범위를 검토한다.
- 게임 지도는 1순위로 `nodeord` 진행도와 정류장 좌표선만 써도 시작 가능하다. 도로 선형은 이후 품질 개선 항목이다.
- 차량 위치가 쌓이면 측정 좌표로 선형을 검증할 수 있다. 시험에서 쓴 "차량 위치와 선의 거리"가 자동 검사 지표 후보다.

### Gaps
- 자동차 프로필과 실제 버스 경로 차이(버스 전용 구간, 회차, 마을 안길)를 검증하지 못했다.
- 긴 노선, 농촌 노선, 일주도로 노선은 시험하지 않았다. 3004 전체 구간 대조도 관측이 있는 14~25번째에 한정된다.
- 정확한 공식 선형(BIS `getLinkInfoByLineId` 추정)과 비교하지 못했다. 호출 허용 여부 확인 후 검토한다.
- FOSSGIS 독일어 상세 정책과 비상업 조건을 읽지 못했다. 상시 서비스에는 쓰지 않는 전제로 둔다.
