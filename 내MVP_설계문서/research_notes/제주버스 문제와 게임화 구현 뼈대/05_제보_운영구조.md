# 커뮤니티 제보·크라우드소싱 운영 구조 (교통·지도 앱 사례와 1인 제주 버스 앱 적용)

> 작성 기준일 2026-11-06. 법률 항목은 일반 정보이며 법률 자문이 아니다. 조문은 law.go.kr 직접 조회가 실패해 법령 미러(nepla.ai)와 해설 글로 확인했다. 출시 전 국가법령정보센터 원문으로 다시 확인해야 한다.
> 표시: "회사 발표"는 해당 기업의 자체 수치로, 독립 검증되지 않았다.

## 1. 각 서비스는 제보를 어떻게 수집·검증·보상·운영하나?

### Takeaway
성공 모델의 공통점은 "제보를 글쓰기가 아니라 앱 사용 중의 한 번 탭으로 만들고, 다른 이용자의 확인으로 검증하고, 돈보다 인정으로 보상한다"는 것이다. 시민 민원형(FixMy계열)의 성패는 기관 응답에 달려 있고, FixMyTransport는 제보 기능이 아니라 교통 데이터 유지 비용 때문에 닫혔다.

### Cited Findings

**비교표**

| 서비스 | 수집 | 검증 | 보상 | 처리/반영 |
|---|---|---|---|---|
| Transit GO | 탑승 중 GPS 공유, 앱 실행 시 탑승 차량을 추정해 시작 제안(AutoGO) | 공개 자료에 교차검증 설명 없음 | 노선별 리더보드, GO 포인트, 감사 표시 | 차량 위치로 즉시 반영 |
| Waze | 앱 내 제보, 지도 이슈 도구 | 다른 운전자 반응으로 노출 시간 변동 | 포인트·커뮤니티 | 자원봉사 편집자가 지도 수정 |
| Moovit | 편집 플랫폼에서 노선 입력 | 공식 자료 없음(검색 범위 내) | 커뮤니티·앰배서더 모임 | 도시 개설 자체를 커뮤니티가 수행 |
| Google Local Guides | 리뷰·수정·장소 추가 | 공개 범위 내 미확인 | 포인트·레벨, 조기 이용·행사 | 지도 반영 |
| OpenStreetMap | 누구나 직접 편집 | OSMCha의 사후 플래그·리뷰 | 비금전 | 즉시 반영 후 사후 검토 |
| Citymapper | 앱 내 'Report Issue' | 팀 내부 검토 + 현장 조사 | 없음 | 내부 데이터 팀이 수정 |
| FixMyStreet / FixMyTransport | 웹 폼, 공개 게시 | 약함(담당 기관이 판단) | 해결 자체 | 기관에 전달, 공개 추적 |
| 당근 동네생활 | 지역 게시판 | 신고 + 불법 게시글 감지 + 가이드라인 | 동네 활동가 선정 | 플랫폼이 조치 |
| 네이버 플레이스 | 정보 수정 제안, 증빙 사진 | 공식 기준 미확인 | 미확인 | 네이버 반영, 사업주는 별도 권한 경로 |
| 국민신문고 | 공식 민원 | 소관 기관 처리 | 없음 | 기관 답변 |

**Transit GO**
- 탑승자 휴대폰 GPS로 실시간 정보가 없는 곳을 채운다. 위치 갱신은 약 1~2초로, 일반 버스 단말 약 15초보다 빠르다는 것이 회사 설명이다 — [Transit 블로그 미러](https://hn.jakechampion.name/reader/https://blog.transitapp.com/autogo)
- 회사 발표: 커버리지는 오타와·라스베이거스·볼티모어·빅토리아에서 차량 운행의 최대 65%, 로스앤젤레스·필라델피아·몬트리올·밴쿠버에서 최대 20%. 월 피드백 응답 약 1천만 건, AutoGO로 시작된 GO 운행 100만 건 이상, 리더보드 조회 월 100만 회 이상, 인앱 설문에서 20%가 게임 요소 때문에 사용 — [같은 글](https://hn.jakechampion.name/reader/https://blog.transitapp.com/autogo)
- 커버리지 지표는 "5분 단위 GO 추적 차량 중앙값 ÷ 전체 차량 중앙값"으로 정의된다 — [같은 글](https://hn.jakechampion.name/reader/https://blog.transitapp.com/autogo)
- 익명 처리, 정확한 위치는 다른 이용자에게 공개하지 않음, 탑승 중에만 공유, 목적지 도착 시 자동 종료, 리더보드에서 닉네임을 숨기는 고스트 모드 제공. Rate-My-Ride로 혼잡·정시성 등을 묻고 기관이 추가 질문을 넣을 수 있다 — [Transit 도움말](https://help.transitapp.com/article/91-what-is-go-crowdsourcing)
- 포인트는 도운 사람 수 기준이고 일부 기관은 유료 구독을 지원한다 — [TransLink](https://www.translink.ca/transitapp)

**Waze**
- 제보 표시 시간은 다른 이용자의 반응 수에 따라 달라진다 — [Waze 지원 문서](https://support.google.com/waze/answer/6125653), [Waze 포럼](https://www.waze.com/discuss/t/how-to-deal-with-bogus-reports/195664.md)
- 지도 이슈는 자원봉사 편집자 화면으로 들어가며, 포럼 답변은 다수가 처리 불가능한 제보인데도 봉사자 노력을 쓴다고 말한다 — [Waze 지원 문서](https://support.google.com/waze/answer/7101380), [Waze 포럼](https://www.waze.com/discuss/t/how-to-deal-with-bogus-reports/195664.md)
- 일부 지역 주민이 통행을 돌리려 허위 제보를 넣은 사례가 보도됐다. 편집자 36만 명 이상이라는 수치는 2016년 자료다 — [Civil Beat](https://civilbeat.org/2016/06/civil-geeks-a-people-powered-navigation-app/)

**Moovit**
- 회사 발표: 편집자 수 2016년 3만 명 이상 → 2017년 20만 명 → 2018년 30만 명. 2019년 자료는 62.5만 명과 "50만 명 이상"이 혼재해 정확한 값이 불확실하다 — [Moovit 블로그](https://moovit.com/blog/5-million-stops-mooviter/), [Moovit 블로그](https://moovit.com/blog/mooviter-milestone/amp/)
- 회사가 개설한 도시의 약 65~70%를 Mooviter가 담당했다고 밝혔다 — [Moovit 블로그](https://moovit.com/blog/moovit-versus-google/)
- 공공 데이터가 없는 곳에서 지역 주민이 자기 지역 노선을 입력하는 구조이며, 크로아티아 첫 도시도 커뮤니티로 개설했다 — [Croatia Week](https://www.croatiaweek.com/?p=39337)

**Google Local Guides**
- 공식 점수표: 수정 5점, 장소 추가 15점 등, 레벨 1(0점)~레벨 7(5,000점)까지 공개. 조건은 변경될 수 있고, 삭제된 폐업 장소의 기여 점수는 레벨에 반영되지 않는다. 혜택은 신기능 조기 이용과 행사 초대 — [Google 지원 문서](https://support.google.com/local-guides/answer/6225851?hl=en-GB)

**OpenStreetMap**
- OSMCha는 변경 묶음을 기하·태그·규모·기여자 행동 규칙으로 표시하고, 규칙 일부는 시간이 지나며 바뀌었다 — [ISPRS 2026](https://isprs-archives.copernicus.org/articles/L-4-W1-2026/275/2026/isprs-archives-L-4-W1-2026-275-2026.pdf)
- 2015년에 만들어졌고 Mapbox 지원 후 2023년 OSM US 프로젝트가 됐으며, 기계학습이 수기 규칙을 대체하는 중이라고 밝힌다 — [OSMCha 소개](https://github.com/OSMCha/osmcha-frontend/blob/master/ABOUT.md)
- 훼손 탐지 분류기는 학습한 지역에서는 잘 작동했지만 낯선 지역에서는 성능이 떨어졌다 — [ISPRS IJGI 2020](https://doaj.org/article/67d708a8bf5e41f6af731c830a6f806e)

**Citymapper**
- 이용자 피드백을 팀이 확인해 OSM을 고치고 현지 데이터 분석가가 현장 조사를 한다 — [OSM Wiki](https://wiki.openstreetmap.org/wiki/Citymapper)
- 앱 내 'Report Issue'를 공식 경로로 안내한다 — [Citymapper FAQ](https://citymapper.com/news/141/frequently-asked-questions)
- 커뮤니티 편집 조직이라기보다 "제보 + 내부 수리" 모델이며, 1인 앱에 가장 가깝다(아래 추론 참고).

**FixMyStreet / FixMyTransport**
- 첫 제보가 고쳐진 이용자는 다시 제보할 가능성이 54% 높았다(약 40만 건 분석, 세계은행 연구진 협업). 상세 설계는 글에 없고 상관관계로 읽어야 한다 — [mySociety](https://www.mysociety.org/2015/03/10/local-government-you-can-shape-your-own-responsible-citizens/)
- FixMyStreet 제보자 중 약 40~50%는 초기 연도를 제외하면 처음 시의회에 신고한 사람이었고, 한 달 뒤 해결 여부를 묻는 짧은 설문을 썼다 — [TICTeC 2018 발표](https://www.slideshare.net/mysociety/what-research-has-mysociety-been-doing-internally-alex-parsons-mysociety)
- 소득이 높은 지역 주민이 제보할 가능성이 높다 — [CDRC](https://www.cdrc.ac.uk/research/population-housing-and-infrastructure/fixmystreet-micro-geographies-of-civic-engagement-and-neighbourhood-environmental-quality/)
- FixMyTransport는 운영사에 1만 건 이상을 보냈고 월 최대 25만 방문을 기록했다. 그러나 교통 데이터 갱신이 자동화되지 않아 유지 비용을 감당하지 못해 2015년에 닫았다 — [mySociety](https://www.mysociety.org/2015/01/29/fixmytransport-needs-a-new-owner/)

**TransitScreen**
- 제보 플랫폼이 아니라 건물·호텔 등에 실시간 교통 정보를 띄우는 디스플레이 회사다. 일부 자료는 Actionfigure로 이름이 바뀌었다고 설명한다. 이번 검색에서 이용자 제보 기능은 확인되지 않았다 — [Wikipedia](https://en.wikipedia.org/wiki/Actionfigure), [Multi-Housing News](https://www.multihousingnews.com/transitscreen-displays-real-time-info-for-tods/)

**당근 동네생활**
- 하루 수만 개 글이 올라온다는 소개가 있다 — [eopla](https://eopla.net/magazines/20386)
- 가이드라인 2.0으로 신뢰·존중을 강화하고 불법 게시글 감지 기술을 고도화한다고 밝혔다 — [디지털투데이](https://ditoday.com/?p=74974)
- 글·사진·제목·가격을 함께 보는 TensorFlow 모델을 썼다. 중고거래 중심이어서 동네생활에 바로 적용하기는 어렵다 — [Google Cloud 사례](https://cloud.google.com/customers/daangn-market?hl=ko)
- 동네 활동가를 선정해 활동 이용자를 인정한다 — [유니콘팩토리](https://www.unicornfactory.co.kr/article/2024041509361580236)

**네이버 지식iN / 플레이스**
- 지식iN은 2024년에 질문 마감을 없애고 복수 채택·답변 투표를 도입했다 — [아시아경제](https://www.asiae.co.kr/en/article/2024042509192578717)
- 플레이스 정보 수정은 로그인 후 업체를 찾아 항목을 골라 사진과 함께 제출하고, 폐업은 증빙 사진을 요구한다. 2차 자료 기준이다 — [Infoarounds](https://infoarounds.com/%EC%9D%BC%EC%83%81%EC%86%8D-%ED%95%84%EC%9A%94%EC%A0%95%EB%B3%B4/naver-map-place-hours-closure-correction/)

**국민신문고**
- 국민권익위 민원빅데이터 API는 국민신문고와 지자체 창구 자료를 집계해 발생지·성별·연령대별 건수를 제공한다 — [공공데이터포털](https://www.data.go.kr/data/15114773/openapi.do)
- 온라인 민원 처리 기간은 근무일 기준 7일로 안내된 자료가 있다. 비공식 해설이라 낮은 신뢰도로 다룬다 — [StudyGov](https://studygov.kr/blog/0342-government24-delay-response-guide/)

### Inferences
- jejubus에 가장 맞는 모델은 Citymapper식 "제보 + 운영자 수리"다. 개방 편집(OSM, Moovit)은 규모가 있어야 검토가 작동한다.
- Waze의 반응 기반 검증은 같은 정류장에 복수 이용자가 있어야 작동한다. 초기에는 공공 BIS 데이터와의 대조가 대체재가 될 수 있다.
- 보상은 Transit·Local Guides처럼 노선별 인정과 도움 수로 충분하다. 현금성 보상은 허위 제보 유인을 만들 수 있다.

### Gaps
- Transit 글의 작성 시점이 불명확하고, 차량 매칭·허위 위치 걸러내기 방식은 공개되지 않았다.
- Waze 허위 제보 비율과 검증 정확도에 관한 독립 연구를 찾지 못했다.
- Moovit 편집 검수 절차, Local Guides 2024~2025 변경, 네이버 플레이스 검수 기준과 포상 여부는 공식 자료로 확인하지 못했다.

## 2. 콜드 스타트는 어떻게 넘겼나?

### Takeaway
확인된 사례는 공통으로 "데이터가 없어 불편이 큰 좁은 범위"에서 시작했다. 1인 앱은 전 노선이 아니라 소수 노선을 골라 운영자가 첫 제보를 직접 만들고, 이용자가 앱을 열 때 질문을 띄우는 방식이 현실적이다.

### Cited Findings
- Transit은 2016년 12월 실시간 버스 데이터가 없던 몬트리올에서 시작했고, 몇 주 뒤 샌프란시스코 Muni 피드 장애 때 확장했다. 2018년에 지원 도시 전체로 넓혔다 — [Transit 블로그 미러](https://hn.jakechampion.name/reader/https://blog.transitapp.com/autogo)
- Transit은 이용자가 GO를 직접 찾아야 했던 문제를 AutoGO로 풀었고, 실시간 정보 장애 때 피드백 요청을 띄운다 — [같은 글](https://hn.jakechampion.name/reader/https://blog.transitapp.com/autogo)
- Moovit은 공공 데이터가 없는 지역의 편집자에게 노선 입력을 맡겼다 — [Moovit 블로그](https://moovit.com/blog/5-million-stops-mooviter/)
- 당근은 중고거래가 성장한 뒤 일부 지역에 동네생활 탭을 만들어 시험했다 — [eopla](https://eopla.net/magazines/20386)
- Andrew Chen은 서비스가 유용해지는 최소 단위를 atomic network로 설명한다 — [요약 노트](https://notes.laratranslate.com/andrew-chen-the-cold-start-problem-how-to-start-and-scale-network-effects-talks-at-google-ef7d2bfd/summary)
- FixMyTransport는 메시지당 평균 약 50명이 읽었고 자원봉사자와 이용자가 다음 행동을 제안했다 — [mySociety](https://www.mysociety.org/2012/08/31/fixmytransport-one-year-on-the-operators-who-wont-play-ball/)

### Inferences
- 제주 초기 범위는 1~2개 노선 또는 정류장 묶음으로 잡는다. 범위 선정 근거로는 민원 최다 유형인 무정차(3절)가 적합하다.
- 운영자가 첫 제보를 직접 만드는 경우 "운영자 확인"으로 표시한다. 이용자 활동처럼 꾸미면 신뢰와 표시 문제가 생길 수 있다.
- 첫 제보는 빈 게시판 글쓰기가 아니라 "버스가 도착했나요? 예/아니오" 같은 한 번 탭 질문으로 받는다. Transit의 대량 피드백은 프롬프트에서 나왔다.
- 앱 제보가 공식 창구보다 쉬워야 한다는 전제에서, 제보 후 공식 민원 경로를 안내하면 이용자에게 즉시 가치를 줄 수 있다.

### Gaps

## 3. 제주 시민 제보 제도와 공공 파트너십, 개선으로 이어진 사례

### Takeaway
제주의 공식 신고는 이미 처분으로 이어진다. 2022~2024년 1,534건 중 약 90%가 주의·경고 또는 과징금·과태료였다. 따라서 앱은 민원을 경쟁 수집하기보다 "공식 창구에 잘 전달되는 근거"와 "데이터 오류 수정"에 집중하는 편이 낫고, 허위 전달은 기사에게 실제 불이익을 줄 수 있다.

- 14세 미만 가입을 받지 않거나 비로그인 제보로 시작하면 부담이 줄어든다.

### Gaps
- 제보 게시판 운영자가 제44조의10의 "유통"에 해당하는지, 소규모 운영자의 민사책임 기준(판례)을 원문으로 확인하지 못했다. 변호사 확인이 필요하다.
- 제44조의2 공시 의무가 비공개 제보함에도 적용되는지 확인하지 못했다.
- 버스 기사 사진·얼굴 공개에 관한 개보위 해석례를 찾지 못했다. 「개인정보 보호법 해석 사례집 1.0」 확인이 필요하다.
- 시행령 확정 조문은 2차 해설로만 확인했고 일부 기사는 초안 기준이다.

## 5. 위치정보사업·위치기반서비스사업 신고가 필요한 경우

### Takeaway
핵심 기준은 "특정 개인의 위치를 측위해 서비스에 쓰는가"다. 공공 버스 위치 표시나 이용자가 고른 정류장 제보만이면 부담이 낮을 가능성이 있고, 이용자 GPS를 서버에 저장하거나 Transit GO식으로 공유하면 위치기반서비스 신고·동의 체계가 필요할 가능성이 높다. 1인 사업자는 시작 후 1개월 이내 신고 특례를 살펴야 한다.

### Cited Findings
아래 조문은 [위치정보법 미러](https://www.nepla.ai/law/%EC%9C%84%EC%B9%98%EC%A0%95%EB%B3%B4%EC%9D%98%20%EB%B3%B4%ED%98%B8%20%EB%B0%8F%20%EC%9D%B4%EC%9A%A9%20%EB%93%B1%EC%97%90%20%EA%B4%80%ED%95%9C%20%EB%B2%95%EB%A5%A0) 기준이며 표시 시행일은 2025-10-01(법률 제21066호)이다.
- 제2조: 위치정보는 이동성 있는 물건이나 개인의 장소 정보로 전기통신설비 등을 이용해 측위된 것이다. 개인위치정보는 특정 개인의 위치정보이고 다른 정보와 쉽게 결합되는 경우를 포함한다.
- 제2조: 위치정보사업은 위치정보를 수집해 위치기반서비스사업자에게 제공하는 사업이고, 위치기반서비스사업은 위치정보를 이용한 서비스를 제공하는 사업이다.
- 제5조: 개인위치정보 대상 위치정보사업은 방송미디어통신위원회 등록 대상이며 법인 요건과 물적 시설, 보호조치가 필요하다.
- 제9조: 개인위치정보를 대상으로 하지 않는 경우를 제외하고 위치기반서비스사업을 하려면 신고해야 한다.
- 제9조의2: 소상공인이나 1인 창조기업은 신고 없이 시작할 수 있으나, 1개월이 지나도 계속하려면 개시일부터 1개월 이내 신고해야 한다.
- 제15조·제18조·제19조: 개인위치정보 수집·이용·제공에는 약관 명시와 동의가 필요하고 최소 수집을 지켜야 한다. 제3자 제공은 고지·동의와 즉시 통보(동의 시 최대 30일 범위 묶음 통보)가 필요하다.
- 제16조: 관리·기술적 보호조치와 수집·이용·제공 사실 확인자료의 자동 기록·보존이 필요하다.
- 제40조: 무신고 사업, 무동의 수집 등은 3년 이하 징역 또는 3천만 원 이하 벌금. 제41조: 보호조치 미이행 등은 1년 이하 징역 또는 2천만 원 이하 벌금.
- 1인 창조기업 범위와 확인 경로, 신고 절차에 대한 안내로 다음 2차 자료가 있다. 사업자 스스로 신고 시 수리까지 최대 2주 정도 걸린다는 설명도 있다 — [이현 법률 블로그](https://blog.ehyun.co.kr/location-information-law-violation-entrepreneur-success), [브런치](https://brunch.co.kr/@ihmin/643)

**시나리오별 잠정 판단 (추론 포함, 법률 판단 아님)**

| 구현 | 위치 데이터 | 잠정 판단 |
|---|---|---|
| A. 공공 BIS 차량 위치 표시만 | 버스 위치 | 개인위치정보 아닐 가능성 높음 |
| B. 이용자가 정류장·노선을 직접 선택해 제보 | GPS 없음 | 측위 위치정보가 아니므로 부담 낮을 가능성 |
| C. 내 주변 정류장 찾기, 위치를 단말에서만 사용 | 서버 미전송 | 불명확, 해설서 확인 필요 |
| D. 제보에 GPS 좌표를 붙여 서버 저장 | 계정·기기와 결합 가능 | 개인위치정보 가능성 높음, 약관·동의·신고 검토 |
| E. GO식 실시간 탑승 위치 공유 | 지속 수집 | 신고·동의·확인자료·보호조치 전제 |
| F. 수집 위치를 다른 서비스 사업자에게 제공 | 제3자 제공 | 위치정보사업 등록(법인) 검토 |

### Inferences
- MVP는 A+B로 시작하면 위치법 부담을 크게 줄일 수 있다. 제보 정확도는 GPS 대신 정류장 선택과 BIS 데이터 대조로 보완한다.
- GPS 제보가 필요해지면 정확한 좌표를 정류장 단위로 즉시 변환하고 원본을 버리는 방식을 검토한다. 다만 수집 자체를 없애는 것은 아니므로 법적 평가는 별도로 받아야 한다.
- Transit GO식 기능은 법적·운영 부담이 가장 커서 후순위가 적절하다.

### Gaps
- 단말 내 처리만 하는 경우의 신고 대상 여부를 원문으로 확인하지 못했다. KISA 「위치정보법 해설서」와 방미통위 안내 확인이 필요하다.
- 사업자등록 없는 개인 개발자의 무료·비영리 앱이 "사업"인지, 제9조의2 적용 대상인지 확인하지 못했다.
- 자기 서비스용으로 수집하는 경우 위치정보사업 등록이 필요한지 공식 해석을 확인하지 못했다.
- 위치정보법은 2025-10-01 이후 개정 여부를 미러로 확인하지 못했다. 신고 기관·절차도 최신 안내 확인이 필요하다.

## 6. 품질 지표, 운영 비용, 1인 운영의 AI 활용

### Takeaway
1인 운영 비용의 주범은 제보 분류보다 데이터 유지다. AI는 분류·요약·중복 후보 제시에 쓰되 제재나 외부 전달은 사람이 확정해야 하며, 공개 근거상 LLM 분류 정확도는 단독 자동화를 뒷받침할 만큼 높지 않다.

### Cited Findings
- FixMyTransport 운영에는 하루 10~20분의 지원·관리와 데이터 갱신 자동화 개발자 시간이 필요하다고 mySociety가 설명했다 — [mySociety](https://www.mysociety.org/2015/01/29/fixmytransport-needs-a-new-owner/)
- 싱가포르 환자 민원 1,816건 연구에서 LLM 3종의 평균 일치율은 61.9~68.8%, κ는 0.114~0.623이었다. 공공 교통 데이터는 아니다 — [PMC](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12327907/)
- 311 녹취 문서를 RNN으로 분류하면 수동보다 빠르고 정확하다는 2022년 논문이 있다 — [Applied AI](https://doaj.org/article/4e031c9aa0c846509a34cb38b941aacc)
- 시민 제보를 LLM으로 분류하는 OFFIS 연구가 있으나 수치는 초록 범위에서 확인하지 못했다 — [OFFIS](https://www.offis.de/offis/publikation/how-can-we-help-you-automatic-categorisation-of-urban-problem-reports.html)
- 작은 로컬 모델로 뉴욕 311 민원 10건 중 9건을 분류한 블로그 시험이 있으나 표본이 작다 — [블로그](https://gmcirco.github.io/blog/posts/mini-model-data-extraction/workflow.html)
- 벤더의 "311 티켓 30% 오분류" 같은 주장은 독립 근거를 찾지 못했다 — [Oxmaint](https://oxmaint.com/industries/government/ai-maintenance-triage-311-public-works-requests)
- Transit은 정의가 명확한 커버리지 지표를 공개한다 — [Transit 블로그 미러](https://hn.jakechampion.name/reader/https://blog.transitapp.com/autogo)
- FixMyStreet는 한 달 뒤 해결 여부 설문을 사용했다 — [TICTeC 2018](https://www.slideshare.net/mysociety/what-research-has-mysociety-been-doing-internally-alex-parsons-mysociety)

### Inferences
**권장 처리 흐름**
1. 수집: 유형 탭, 노선, 정류장, 시각. 자유 입력은 선택.
2. 자동 처리: 개인정보 가림, 유형 분류, 욕설·실명 플래그, 같은 노선·정류장·시간대 중복 묶음.
3. 자동 대조: BIS 위치·시간표와 비교해 "근거 있음/없음/판단 불가" 표시.
4. 사람 검토: 하루 한 번 묶음 검토. 삭제 요청과 외부 전달은 사람이 결정.
5. 처리: 앱 데이터 오류는 직접 수정, 서비스 민원은 이용자에게 공식 창구 안내, 패턴은 월간 집계.
6. 마감: "고쳤어요/전달 안내함/확인 불가" 알림. 첫 제보 처리에 우선순위를 둔다.

**제보 유형 분리**
- 데이터 오류(시간표, 정류장, 노선)는 운영자가 고칠 수 있어 빠른 성공 경험을 만들기 좋다.
- 서비스 민원(무정차, 불친절)은 공식 창구로 연결한다.
- 현장 상황(만차, 지연)은 짧은 수명으로 표시하고 Waze식으로 자동 소멸시킨다.

**지표 후보**
- 첫 제보 처리율과 처리 시간.
- 첫 제보 처리 여부별 재제보율. FixMyStreet 54%와 같은 효과가 있는지 확인한다.
- 유효 제보율, 중복률, 삭제 요청 건수.
- 활성 이용자 대비 제보 참여율, 대상 노선 커버리지.
- 제보당 운영 시간. 예산 기준으로 하루 10~20분 수준을 상한 목표로 잡되, 이 값은 영국 사례의 참고치다.

**AI 활용 경계**
- 초기 일정 기간은 모든 AI 라벨을 사람이 확인해 한국어·제주 지명 기준 정확도를 측정한다.
- 계정 제재, 외부 전달, 허위 판정은 자동화하지 않는다. 앱 리뷰의 오판 불만과 위 일치율이 근거다.
- OSMCha 사례처럼 처음에는 규칙을 쓰고, 라벨이 쌓이면 모델을 쓴다. 지역 편향 위험은 제주 데이터로 시험한다.
- 외부 LLM에 제보를 보낼 때는 가림 처리 후 전송하고 처리 위탁 고지를 검토한다.

### Gaps
- 1인 또는 극소 규모 운영사의 AI 모더레이션 실측 비용과 정확도 사례를 찾지 못했다.
- 한국어 민원 LLM 분류 정확도, 임베딩 기반 민원 중복 제거 연구를 찾지 못했다.
- 제보당 단가, 건당 LLM 비용은 조사 범위 밖이며 현재 요금표로 계산해야 한다.
- 교통 앱의 제보 품질 지표 공개 벤치마크(유효 비율, 처리 시간)를 찾지 못했다.
