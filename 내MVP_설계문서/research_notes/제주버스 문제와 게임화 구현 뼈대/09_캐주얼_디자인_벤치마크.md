## 레퍼런스별 벤치마크: 무엇이 놀이 감각을 만드나

### Takeaway
놀이 감각은 대부분 **색과 도형의 절제 + 사건에 맞춘 짧은 움직임 + 사람 같은 말투**에서 나온다. 3D나 고급 일러스트가 필수는 아니다. 공통 원리는 다섯 가지다.
1. 형태를 먼저 단순화한다(Duolingo, Tossface).
2. 배경을 죽이고 주인공만 채도를 높인다(Pokémon GO 초기, Transit).
3. 의미가 있는 순간에만 크게 움직인다(토스).
4. 지도 위에 내 흔적이 남는다(Zenly, Bump, Pikmin Bloom).
5. 농담은 기능을 방해하지 않는 자리에만 둔다(Citymapper, Transit).

- "Juice"는 메커닉을 더하지 않고 효과를 층층이 쌓아 손맛을 만드는 기법이다. 출발점은 2012년 Nordic Game Jam의 "Juice it or lose it" 발표다 — [itch.io 정리](https://crcdng.itch.io/juicy-break) [요약확인]
- 화면 흔들림은 0.2초 미만, 그리고 끌 수 있게 하라는 개발자 조언이 있다 — [개발 블로그](https://alexhoratiogamedev.blogspot.com/2017/04/quick-and-easy-ways-to-add-game-juice.html) [요약확인]
- 반론: 효과 자체가 목적이 되면 본래 목표에서 주의를 뺏는다 — [RPG Playground](https://rpgplayground.com/research-making-a-juicy-game/) [요약확인]

### Inferences
- 한국 10~30대가 일상에서 보는 품질 기준은 토스다. 제주버스가 토스를 넘어 "더 게임스러워질" 필요는 없다. 토스 수준의 절제에 **제주 소재와 노선색**만 더해도 차별화된다. [가설]
- 교통 앱 벤치마크들의 재미는 그래픽이 아니라 **말투**에서 나온다(Transit, Citymapper). 비용이 거의 들지 않으므로 가장 먼저 해볼 일이다. [가설]
- Forest와 Duolingo의 손실 회피는 교통에 위험하다. 결행이나 지각의 책임은 사용자에게 없다. Finch의 무처벌이 더 맞다. [가설]
- Zenly의 변화(사탕 코너 → 절제)는 10대 취향 앱도 나이가 들면 색을 줄인다는 사례다. 첫 버전부터 많은 색을 쓰지 않는 편이 낫다. [가설]

### Gaps
- TDS의 공식 모션 원칙 문서는 찾지 못했다. 토스가 Rive를 쓰는지도 확인 못 했다.
- 네이버 지도, 카카오맵 안의 캐릭터 표시 기능은 확인 못 했다. 카카오 프렌즈의 앱 UI 내 사용 사례도 구체 자료가 없다.
- GDC 자료는 Pokémon GO 발표(2017)의 2차 보도만 확보했다.
- Zenly 서비스 종료 시점과 경위는 이번에 원문으로 확인하지 못했다. Snap Map 현행 UI, Bump 최신 UI, 駅メモ! 체크인 연출은 영상이나 앱 직접 확인이 필요하다.
- Mobbin, Behance, Dribbble 사례 글은 이번 범위에서 수집하지 못했다.

## 지도를 게임 맵처럼 만드는 시각 방법과 제주 상징

### Takeaway
권장 순서는 **실제 지도의 채도를 낮추고, 노선과 버스만 선명하게 한다**이다. 일러스트 지도는 길찾기 대체가 아니라 수집 화면 전용으로 분리한다. 프로젝트는 이미 "가짜 SVG 지도를 실제 지도로 교체"한 이력이 있고, Pokémon GO도 지도를 과하게 꾸미자 현실과 어긋나 되돌렸다. 제주 소재 중 귤, 오름, 현무암, 바람은 안전한 편이고 돌하르방, 해녀, 제주어는 고증과 존중 검토가 필요하다.

- 공유율, 공유 후 유입 등 공유 카드의 정량 효과는 공개 자료를 찾지 못했다.
- Strava 2025판 디자인 과정, Wrapped의 디자인 시스템 상세는 공식 자료가 없었다.

## 접근성과 게임 끄기 모드

### Takeaway
게임 끄기는 부가 설정이 아니라 **구조적 기본값**으로 설계한다. 정보 층과 표현 층을 분리해서, 표현 층을 빼도 모든 기능이 그대로 작동해야 한다. 글자 크기와 모션은 기기 설정을 따르는 토스 방식이 시니어 전용 화면보다 유지비가 낮다.

### Cited Findings
- WCAG 2.2 1.4.1(A등급): 색만으로 정보를 전달하면 안 되고 도형, 글자, 패턴을 병행 — [W3C](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html) [본문]
- WCAG 2.2 2.5.8: 터치 대상 최소 24×24 CSS px(간격 등 예외) — [W3C](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) [본문]
- WCAG 2.2 2.3.3(AAA): 상호작용으로 발생하는 움직임은 끌 수 있어야 함, prefers-reduced-motion이 충분 기법 — [W3C](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html) [본문]
- 토스는 iOS 9단계, 안드로이드 12단계 기기 글자 크기를 모두 반영하고 다크 모드를 자동 적용. 드래그 대신 탭으로 옮기기 지원 — [토스피드](https://toss.im/tossfeed/article/mobile-accessibility) [본문] [회사발표]
- 토스가 큰 글씨 대응 때 버튼 말줄임과 어색한 줄바꿈 문제를 겪음 — [디지털 인사이트](https://ditoday.com/?p=73830) [요약확인]
- 부모님 폰 글자 설정을 키우면 토스도 커진다는 안내. 별도 고령자 모드가 아닌 기기 연동 방식 — [토스피드](https://toss.im/tossfeed/article/tosswithparents) [요약확인]
- 신한투자증권 간편모드: 주요 화면 글씨 20% 확대, 절차 단순화 — [아시아경제](https://www.asiae.co.kr/en/article/2025120209523971033) [요약확인]
- 색각이상 유병: 경기도 일부 지역 연구 남성 6.64%, 선천성은 남성 3.54%, 여성 0.41% — [KoreaScience 게재 논문, 2011](https://koreascience.kr/article/JAKO201117760832239.page?lang=ko) [요약확인]
- 동아시아계 남성의 선천성 적록 이상은 4~6.5% — [PubMed 리뷰](https://pubmed.ncbi.nlm.nih.gov/22472762/) [요약확인]
- Mini Motorways는 색약 친화 팔레트와 도로색 선택 제공 — [Gamespress](https://gamespress.com/Best-Selling-Strategy-Sim-Mini-Motorways-Speeds-into-the-Holiday-Seaso) [요약확인]
- 프로젝트 현황: styles.css에 prefers-reduced-motion 전역 처리가 이미 있음. 반면 `.preview-pill` 9px, `.best-tag` 9px, `.eyebrow` 10px, `.map-bottom` 8px 등 **매우 작은 글자**가 다수 — [styles.css](../../../web/public/styles.css)

### Inferences

**층 분리 설계** [가설]
- **정보 층**: 노선, 번호, 도착 정보, 지도, 알림, 공식 공지. 게임 켜짐 여부와 무관.
- **표현 층**: 표정, 도장, 하늘 띠, 축하, 말투 일부, 사운드.
- HTML에 `data-game="on|off"`를 두고, 표현 층을 CSS로 제거한다. 테마 토글과 같은 구조라 재사용이 쉽다.

**설정 3개** [가설]

| 설정 | 기본값 | 끄면 |
|---|---|---|
| 게임 모드 | 첫 실행에서 선택. 언어가 ko 외이거나 빠른 사용 흐름이면 끔 후보 | 캐릭터, 도장, 축하, 보상 알림 제거. 데이터 기능은 동일 |
| 움직임 | 기기 설정 따름 | 토큰은 칸만 바꾸고 애니메이션 없음 |
| 글자 크기 | 기기 설정 따름 + 앱 내 크게 | 큰 숫자 우선 레이아웃 |

- 첫 화면에서 "게임 모드 켤까요?"를 강요하지 않는다. 이용자 대부분은 게임 때문에 쓰지 않는다는 04의 해석과 맞다. 도착 정보를 처음 본 뒤 작은 제안을 하는 쪽이 낫다.
- **색 구분 대응**: 제주 4색 중 빨강(급행)과 초록(지선)이 적록 색약에서 겹칠 수 있으므로 등급 도형과 글자 라벨을 항상 병행한다. 이는 WCAG A등급 요구이기도 하다.
- **앱 브랜드색 문제**: 현재 주색 #2167ff는 간선 파랑과 겹친다. 버튼과 노선이 같은 색이면 의미가 섞인다. 주색을 바꾸거나, 노선색을 칩과 몸통에만 쓰는 규칙이 필요하다.
- **작은 글자 정리는 게임화와 별개로 선행한다.** 8~10px 표기는 고령층뿐 아니라 야외 정류장에서 누구에게나 불리하다. 최소 12px를 제안한다.
- 큰 글씨 대응 시 버튼 라벨과 큰 숫자가 말줄임되지 않는지 테스트한다. 토스도 겪은 문제다.
- 게임 끄기는 **단순함이 필요한 사람의 선택**이므로 깊은 메뉴에 숨기지 않는다.
- 스크린리더: 캐릭터 표정은 대체텍스트 대신 상태 문장으로 읽는다. 예: "데이터 3분 전 수신". 귀여운 설명 대신 정보를 읽어야 한다.

### Gaps
- 노인 대상 버스 앱 게임 모드 사례는 찾지 못했다. 네이버 앱의 시니어 전용 모드 자료도 없음.
- 한국 고령 이용자의 게임 표현 수용도 자료는 미확보.
- 제주 관광객 고령층 비중, 다국어 이용 시 게임 문구 번역 품질은 미조사.
- "최소 12px"는 내 제안이며 특정 표준 근거가 아니다. WCAG는 고정 px 최소치를 이 조사 범위에서 확인하지 않았다.

**캐릭터 제작 절차** [가설]
1. AI는 발상에만 쓴다. 프롬프트에 특정 게임, 캐릭터, 작가, 회사 이름을 넣지 않는다.
2. 최종안은 사람이 벡터로 직접 그린다. 수정 과정을 파일로 남긴다.
3. 실제 마커 크기에서 실루엣을 확인한다.
4. 키프리스와 이미지 검색으로 유사 상표·캐릭터를 확인한다(특히 하르방, 귤 캐릭터).
5. 지역 캐릭터 상표를 장기 자산으로 삼으려면 등록 전 법률 확인을 받는다.

- 순수 AI 마스코트는 남이 베껴도 막기 어렵고, 유사물 침해 책임은 사용자에게 올 수 있다. 양쪽으로 불리하다.
- 벤치마크를 "참고"할 때도 실루엣, 색 조합, 비율까지 가까우면 위험하다. 이 문서의 원리는 표현이 아니라 **구조**로만 차용한다.

### Gaps
- 공식 사용량 또는 가격으로 비교한 Lottie 플레이어 크기, 실제 앱에서의 프레임 성능은 미측정. 저가 안드로이드 기기 테스트 필요.
- Midjourney 등 이미지 서비스의 현행 약관과 소유권, 캐릭터 일관성 기능은 확인 못 했다. 쓰기 전 약관 직접 확인 필요. 이는 유료 서비스이므로 승인 대상이다.
- 안내서 원문을 직접 읽지 못했다. 등록 실무는 한국저작권위원회 원문 확인 필요. 이 항목은 법률 자문이 아니다.
- OpenFreeMap의 상업 이용 조건과 안정성, 제주 지역 표기 품질은 미검증.

## 제주버스 디자인 방향 3안

### Takeaway
권장안은 **A "노선 보드"를 바닥으로 깔고, C "내 제주 지도"를 얇게 얹고, B "귤버스"는 표정 토큰 수준으로 제한**하는 순서다. A는 실용성을 해치지 않고 비용이 가장 낮다. C는 공유와 재방문 소재를 준다. B의 본격 마스코트는 상표·제작 부담이 커서 수요가 확인된 후로 미룬다.

### Inferences

아래 3안은 모두 [가설]이다. 효과 수치는 없고 사용자 테스트로 고를 대상이다. 일정은 대략의 감이다.

#### 공통 바닥 (어느 안이든 먼저)
- 8~10px 글자 정리, 최소 터치 영역 확보.
- 지도 채도 낮춤, 노선색 강조.
- 등급 도형 체계, 노선 칩 재설계.
- 데이터 나이 표시와 큰 도착 숫자.
- `data-game` 층 분리.

#### A안. "노선 보드" (Mini Metro + Transit + 토스)

**한 줄**: 지도는 조용하게, 노선이 게임판이 된다.

**보이는 모습**
- 지도는 낮은 채도. 진하고 둥근 노선 선이 주인공.
- 큰 도착 숫자 아래 노선을 일직선으로 편 보드가 있다. 정류장은 칸, 버스는 둥근 말. 데이터가 오면 한 칸 톡 이동.
- 등급 도형, 현무암 점무늬, 돌담 구획선. 귤색 포인트 하나.
- 캐릭터 없음. 말투만 가볍다.

**모션**: 칸 이동, 작은 호흡, 탑승 체크. 사운드 없음, 짧은 진동만 지원 시 사용.

| 장점 | 단점 |
|---|---|
| 실용성 손실이 거의 없음 | 스크린샷의 임팩트가 약함 |
| 게임 끄기가 거의 필요 없을 정도로 절제됨 | 10대에게 "게임"처럼 안 느껴질 수 있음 |
| CSS, SVG로 가능. 저작권 부담 최소 | 수집 동기가 없으면 재방문 소재 부족 |
| 다국어, 고령층, 관광객에게 그대로 사용 가능 | 정확한 공식 데이터가 없으면 보드가 비어 보임 |
| 30대까지 수용 가능 | 노선 선형과 정류장 순서 데이터 품질에 의존 |

**구현 감**: 1~2주. 추가 비용 없음.

#### B안. "귤버스 친구들" (Duolingo + 타요 + Actionmoji + Finch)

**한 줄**: 버스마다 얼굴이 있고, 데이터 상태가 표정이 된다.

**보이는 모습**
- 지도 위 버스가 둥근 얼굴 캐릭터. 노선색이 몸, 번호가 가슴.
- 등급별로 성격을 부여: 급행은 날렵, 간선은 듬직, 지선은 동네 친구, 관광지순환은 여행자.
- 정류장에는 절제된 돌하르방 수호자가 무표정으로 서 있음. 도장을 찍어줌.
- 데이터 정상이면 또렷, 오래되면 졸림, 끊기면 물음표.
- 굵고 둥근 글씨, 큰 모서리, 채도 높은 버튼.

**모션**: 캐릭터별 짧은 도착 인사, 하차 후 작별. Rive 후보. 기본 무음.

| 장점 | 단점 |
|---|---|
| 스크린샷과 스티커, 굿즈로 확장 쉬움 | 30대와 관광객에게 유치해 보일 위험 |
| 10대 호감 가능성이 가장 높음 | 마스코트 제작과 상표 확인 비용이 큼 |
| 데이터 지연을 귀엽고 솔직하게 표현 | 결행, 불만 상황에서 캐릭터가 조롱거리가 될 수 있음 |
| 지역 기관·운영사 협업 소재 | 작은 마커에서 표정이 안 보임, 지도 혼잡 |
| 브랜드 기억성 최고 | 지속 운영(시즌, 표정 추가) 부담 |

**구현 감**: 토큰형 1~2주, 다상태 캐릭터 4~8주. 외주나 Rive 유료 시 사전 승인 필요.

#### C안. "내 제주 지도" (Zenly 오버레이 + Bump + Pikmin + 서울 스탬프 + Wrapped)

**한 줄**: 버스를 탈수록 흑백 제주가 색으로 물든다.

**보이는 모습**
- 평소 앱은 A처럼 조용하다.
- 별도 "내 제주" 탭에 일러스트 섬 지도. 탄 구간이 노선색으로 칠해지고 정류장 도장이 찍힘.
- 동서남북 권역 완성 카드, 성격 카드, 여행 리캡 공유.
- 여기만 필름이나 종이 느낌. 하늘 띠는 시간대 변화.

**모션**: 탑승 후 색 번짐. 큰 보상 때만 전체 화면.

| 장점 | 단점 |
|---|---|
| 실제 탑승을 시각화해 앱 목적과 일치 | 탑승 인증과 위치 처리가 필요 |
| 공유 소재가 가장 강함 | 도민은 고정 노선만 타서 금방 정체될 수 있음 |
| 정보 화면과 분리되어 게임 끄기가 쉬움 | 완주 후 소진(04의 수집 판정과 같음) |
| 관광객 여행 리캡과 궁합 좋음 | 민감한 이동 기록. 저장 방식과 만 14세 미만 정책 필요 |
| 흑백→컬러는 저비용으로 큰 효과 | 탭을 안 열면 존재감 없음 |

**구현 감**: 경량판 2~4주(기기 내 저장 기준). 탑승 인증 정확도에 따라 증가.

#### 권장 순서
1. **공통 바닥 + A안**. 게임 표현 이전에 "똑똑하고 예쁜 버스 앱"이 된다.
2. **B의 표정만 차용**. 버스 말에 데이터 상태 눈 2~3종. 이름과 세계관은 붙이지 않는다.
3. **C 경량판**. 기기 내 저장, 흑백→컬러, 공유 카드 1종.
4. 10대 반응이 강하면 B를 본격화한다. 이때 해녀, 돌하르방 소재는 자문을 거친다.

#### 빠른 검증 방법
- 세 안의 정지 화면을 10대, 20대, 30대, 60대 각 3~5명에게 보여 준다. "이 버스가 언제 오나요?"를 몇 초에 답하는지 측정하고, 그다음 "쓰고 싶은가"를 묻는다.
- **첫 질문의 답을 찾는 시간이 현재 화면보다 늘면 그 안은 탈락**시킨다.
- 실제 공식 도착 데이터가 없는 단계의 시안에는 예시임을 명확히 표시한다.

### Gaps
- 3안 모두 실제 사용자 테스트 전이다. 대상 연령별 선호는 내 판단이지 데이터가 아니다.
- 구현 기간은 실제 코드 분석 없이 낸 추정이다.
- 게임 표현이 도착 정보 인지 속도를 얼마나 늦추는지에 대한 교통 앱 연구는 찾지 못했다.
- 실시간 연동이 끝나지 않은 상태에서는 A의 보드 품질을 검증할 수 없다. 현재 실연동 상태는 09·10 문서로 확인해야 한다.
